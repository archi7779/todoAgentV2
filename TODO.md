## 1) Отмена по клику

Сквозная цепочка «кнопка Стоп → SDK»:

1. **Клиент:** в компоненте создаём `AbortController`, отдаём `controller.signal`
   в `api.post('/api/protected/agent', body, { signal })`; по клику — `controller.abort()`.
2. **Роут:** у Next `Route Handler` есть `request.signal`, который срабатывает при
   разрыве соединения клиентом. Прокидываем вниз: `runAgent(input, { signal: request.signal })`.
3. **Агент → провайдер:** тот же сигнал уходит в `chat(messages, { signal })`.

Итог: генерация останавливается сразу, токены не тратятся.

**Учесть:**
- `AbortError` — это НЕ ошибка. Не логировать как `error`, не показывать юзеру как сбой
  (в клиентском слое уже есть паттерн `CanceledError` — переиспользовать).
- Нужно чистить UI-состояние «идёт генерация» после отмены.

## 2) Отмена по таймауту

Пользователь может не нажать «стоп», поэтому нужен потолок на один вызов LLM:

```
AbortSignal.any([request.signal, AbortSignal.timeout(60_000)])
```

- Таймаут для LLM **длиннее** дефолтных 10s из `lib/api` — вызовы медленные, бери 30–120s.
- Помнить про `maxDuration` у Next route — он режет сверху (отдельный уровень).
- Нужен **два** уровня таймаута:
  - per-request (на один вызов модели),
  - overall (на весь прогон агента целиком — см. п.4).

## 3) Лимит по токенам — кто отвечает?

**Ответ: приложение (твой оркестратор), а НЕ провайдер.**

Провайдер ограничивает только это:
- `max_tokens` / `max_completion_tokens` — потолок **выхода** у **одной** генерации.
- Он **не** считает:
  - входные токены,
  - накопленный расход за весь прогон (несколько итераций агента),
  - бюджет конкретного пользователя,
  - стоимость в деньгах.

Значит, ответственность на нас:
- Перед вызовом: проверять оставшийся бюджет пользователя (поле в БД, например `credits`).
  Нет бюджета → не вызывать модель вообще.
- После каждого ответа: считывать `usage` (input/output) и **вычитать** из бюджета.
- Перед следующей итерацией цикла: если бюджет превышен → `break` и вернуть понятную ошибку/частичный результат.

`AbortSignal` тут — не основной механизм: бюджет логичнее проверять **между** вызовами
(break в цикле). Но если хочется резать и **во время** стрима (уже видно, что выход
разогнался), можно абортить по подсчёту токенов в потоке.

## 4) Защита от зацикливания

**Ответ: это делает оркестратор агента, а не провайдер.** Провайдер вообще не знает,
что ты запускаешь цикл — он отвечает на один вызов.

Правильная защита — комбинация (не что-то одно):

- **Лимит итераций** (`maxIterations`, напр. 10) — главный и обязательный барьер.
  Дошли до потолка → стоп с внятной ошибкой.
- **Общий бюджет токенов/стоимости** — см. п.3. Если суммарно превысили → стоп.
- **Общий лимит времени** (wall-clock) на весь прогон — отдельно от per-request таймаута.
  Годится тот же `AbortSignal.timeout(overallLimit)`.
- **Детект повторов** — если модель N раз подряд вызывает один и тот же инструмент
  с теми же аргументами → считаем зацикливанием, останавливаемся.
- **Детект «нет прогресса»** — модель не делает tool-call и не выдаёт финальный ответ,
  просто повторяет текст → стоп.
- **Требование финала** — нормальное завершение = ответ без вызова инструментов.
  Не дождались за лимит итераций → завершаем принудительно.

Практическое правило: **дёшево рвём по итерациям и бюджету между вызовами**,
а `AbortSignal` используем для жёсткого обрыва in-flight запроса (клик / таймаут).

## Обработка ошибок LLM-слоя (`LLMError`)

Отдельный словарь на границе «агент ↔ провайдер». НЕ клиентские `ApiError`
(те про HTTP-ответы нашего API) и НЕ `AppError` (то вообще про HTTP).
Поток: `LLMError` → роут переводит в `AppError` → `mapHttpError` → `ApiError`.

### Уже сделано ✅

- `src/agent/errors.ts`: `LLMError`, `ConfigurationError`, `NotSupportedError`,
  `NetworkError`, `TimeoutError`, `CanceledError`, `ProviderError`, `AuthError`,
  `RateLimitError`, `ContextLengthError`.
- `mapProviderError(error, provider, ctx)` — структурный маппинг ошибок SDK
  (по `status`/`signal`/тексту, без импорта SDK):
  - `signal.aborted` / `AbortError` → `CanceledError`
  - `timedOut` → `TimeoutError`
  - 401/403 → `AuthError`, 429 → `RateLimitError` (+ `retryAfter`),
    400/413 с признаками context length → `ContextLengthError`
  - прочие статусы → `ProviderError` (retryable только 5xx)
  - без статуса → `NetworkError`
- Оба провайдера оборачивают `chat`/`chatStream`/`embed` в `mapProviderError`.
- `getProvider()`/`need()` бросают `ConfigurationError`; `embed()` у Anthropic — `NotSupportedError`.
